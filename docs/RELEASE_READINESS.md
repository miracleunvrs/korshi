# Korshi — готовность расширенного релиза

## Что работает без внешних провайдеров

- заявки: фото, видео до 10 МБ, комментарии, назначение, SLA, приоритет, история, «до/после», рейтинг, повторное открытие, общедомовой режим, фильтры и объединение дублей;
- центр уведомлений и серверная модель предпочтений/очереди доставки;
- документы: категории, папки в БД, полнотекстовый индекс, версии, архив, важность, права, область дома/подъезда, ознакомление и статистика; PDF и изображения открываются внутри Web;
- официальные голосования собственников: площадь/доля, кворум, неизменяемый бюллетень, сроки, материалы, автозакрытие, CSV и печатный PDF-протокол;
- финансы: баланс, план-факт, операции, месячная визуализация, документы, приватные счета/долги, платежи и квитанции в схеме данных, CSV/PDF-экспорт;
- аварийный центр: затронутые дома/подъезды, ETA, обновления, схема зоны, контакты 109/112, ознакомление и итоговый отчёт;
- QR-пропуска, постоянные/курьерские/автомобильные пропуска, отзыв, журнал проходов, списки, SOS и роли охраны/консьержа;
- парковочные места, гостевая бронь без пересечений, жалобы, въезд/выезд и схема парковки;
- помещения, спортплощадка, мангальная зона, грузовой лифт и парковка: правила, лимиты, согласование, отмена, напоминания и платежный статус;
- работы по дому: типы работ, сотрудники, чек-листы, фото «до/после», геометка, пропуски работ и оценки;
- события, RSVP, лимиты, напоминания, альбомы, клубы/чаты, помощь, потерянное, животные, совместные покупки и обычные опросы;
- маркетплейс: вещи, парковки/кладовые в модели, услуги, проверенный исполнитель, отзывы жителей, рейтинг, жалобы, избранное, чат, архив и платное продвижение в модели;
- несколько квартир/ЖК, переключение контекста, девять ролей, права, семейные приглашения и аудит;
- white-label настройки, цвета, логотип, контакты, домен, категории, роли, правила и RU/KK/EN конфигурация;
- AI-центр с 11 сценариями, изображением, структурированным ответом, источниками и обратной связью;
- offline-очередь Web и Flutter, повтор синхронизации, reduced motion, skeleton, optimistic UI, haptics/pull-to-refresh Flutter;
- rate limiting, события аналитики, webhook idempotency, RLS, CI и отдельный staging env-шаблон.

## Что требует внешних реквизитов

Это не программный TODO: код и таблицы готовы, но действие нельзя честно включить без выбранного поставщика и его production/staging ключей.

| Возможность | Что предоставить | После подключения проверить |
| --- | --- | --- |
| Web/Flutter push | OneSignal или FCM credentials | delivery receipt, deep link, logout token cleanup |
| SMS/email | SMS API и SMTP/email API | шаблоны, opt-out, quiet hours, критический fallback |
| Платежи | merchant account, webhook secret | idempotency, подпись webhook, refund, фискальный чек |
| Домофон/СКУД | модель оборудования, base URL, API key | одноразовость QR, отзыв, event callback |
| Шлагбаум | API контроллера | роли, журнал команды, подтверждение устройства |
| ЭЦП/eGov | NCALayer/eGov договор и credentials | подпись hash протокола, сертификат, timestamp |
| Korshi AI | `OPENAI_API_KEY`, `OPENAI_MODEL` | лимиты, стоимость, redaction PII, eval-набор |
| Мониторинг | Sentry/OTel DSN | sourcemaps, release tag, alert routing |

## Применение базы

Миграции `012`–`025` должны применяться строго по порядку к staging, затем к production. После `db push` обновите `src/types/database.types.ts` командой `pnpm db:types`.

Перед production-релизом:

1. Сделать резервную копию Supabase/Postgres и проверить восстановление в отдельный проект.
2. Применить миграции на staging и выполнить RLS-тесты под resident/owner/dispatcher/executor/guard/admin.
3. Проверить подписи и идемпотентность webhook всех подключённых провайдеров.
4. Запустить `pnpm type-check`, `pnpm lint`, `pnpm build`, `pnpm test:smoke`.
5. В `mobile/` выполнить `flutter pub get`, `flutter analyze`, `flutter test`.

## Резервное копирование и восстановление

- ежедневно: provider-managed backup базы;
- еженедельно: логическая копия схемы и данных в зашифрованное хранилище;
- файлы `house-media`: versioning/lifecycle у storage-провайдера;
- раз в месяц: тест восстановления с измерением RPO/RTO;
- секреты и service-role ключи не входят в backup приложения и хранятся в secrets manager.

## Наблюдаемость

`analytics_events` предназначена для product-метрик без ИИН, телефона и содержимого сообщений. Ошибки внешних доставок фиксируются кодом и числом попыток, без секретов и полного payload. Для production нужен DSN выбранного error-monitoring сервиса.
