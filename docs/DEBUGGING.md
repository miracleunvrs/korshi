# Debugging Korshi

## Быстрый алгоритм

1. Воспроизведите проблему на конкретном маршруте и с конкретной ролью пользователя.
2. Откройте DevTools: Console, Network и запрос Supabase.
3. Проверьте auth-сессию, `profiles.id`, `complex_id` и `verified`.
4. Сравните запрос Web с запросом Flutter: таблица, поля, фильтры и текущий user id должны совпадать.
5. Проверьте ответ Supabase и код ошибки до изменения UI.
6. Исправьте источник проблемы: RLS/RPC, repository, store или компонент.
7. Повторите исходный сценарий и прогоните проверки из README.

## Частые симптомы

### «Не удалось сохранить публикацию»

Проверьте:

- пользователь авторизован и подтвердил email;
- профиль существует и `verified = true`;
- профиль привязан к `complex_id`;
- `building_id` и `entrance_id` принадлежат тому же ЖК;
- публикация отправляется через `persistPost`, а не прямым insert из UI;
- для изображения файл сначала загружен в bucket `house-media`.

### Публикация появляется и исчезает

Это обычно ошибка backend после optimistic-добавления. Ищите `backendError` и ответ `persistPost`. Не оставляйте optimistic-элемент без rollback.

### Голос накручивается повторно

Проверьте уникальность `poll_votes(poll_id, user_id)`, обработку ошибки `23505` и отсутствие повторного insert при двойном клике. Защита должна быть в БД, клиентская кнопка — только дополнительный UX-слой.

### Фильтр прокручивает ленту сзади

Модальное окно обязано:

- ставить `document.body.style.overflow = "hidden"` при открытии;
- восстанавливать прежнее значение при закрытии/unmount;
- иметь собственный `max-height` и `overflow-y-auto`.

### Не загружается изображение

Проверьте путь в `post_attachments.url` или `classifieds.image_path`, bucket `house-media`, RLS storage policy и срок signed URL. Абсолютные публичные URL можно оставить без подписи, внутренние пути нужно подписывать через repository.

### Личный чат не создаётся

Проверьте, что target user существует, пользователь подтверждён, а вызов идёт через `create_direct_chat`. UUID-заглушки вроде `user-1` или `chat-1` нельзя отправлять в production Supabase.

### Заявка жителя не принимается

Проверьте роль текущего профиля (`admin`), принадлежность заявки тому же ЖК и вызов `review_verification_request`. Не обновляйте заявку и профиль двумя независимыми запросами: RPC выполняет это атомарно.

## Логи и секреты

Логируйте только идентификаторы сущностей, статус операции и код ошибки. Не выводите access token, API key, service role key, пароль, документ жителя или полный ответ auth. После отладки удалите временные debug-логи.

## Проверки перед передачей

```bash
npm run type-check
npm run lint
npm run build
dart analyze mobile
git diff --check
```

Для изменения БД дополнительно:

```bash
npx supabase db push --dry-run
npx supabase db push
npm run db:types
```

Для security review:

```bash
npm run security:scan
```

Отчёт Strix должен рассматриваться как дополнительная проверка, а не как гарантия отсутствия уязвимостей.
