# Korshi

Korshi — закрытая цифровая среда для жителей жилого комплекса. В репозитории находятся Web-версия на Next.js и мобильное приложение на Flutter, работающие с одной базой Supabase.

## Возможности

- регистрация, вход, восстановление пароля и выход из аккаунта;
- подтверждение статуса жителя через заявку и документ;
- лента публикаций, объявления, услуги, опросы и инициативы;
- защита от повторного голоса и повторной поддержки инициативы на уровне БД;
- комментарии, реакции и снятие собственных публикаций;
- чаты ЖК, домов, подъездов и личные чаты;
- объявления с переходом в личный чат с автором;
- админ-проверка заявок жителей;
- уведомления из Supabase с realtime-обновлением, отдельным центром и персональными настройками;
- загрузка изображений публикаций, вложений чата, заявок и документов в защищённое хранилище;
- центр заявок в ОСИ: вложения, SLA, история обсуждения, исполнитель, оценка и повторное открытие;
- персональный экран «Сегодня» с быстрыми действиями и важными событиями дома;
- динамическое название и адрес ЖК из профиля и таблицы `complexes`;
- защищённый архив документов ОСИ с версиями, важностью и подтверждением ознакомления;
- официальные голосования с кворумом, голосом от квартиры и неизменяемым бюллетенем;
- прозрачный финансовый журнал дома: баланс, доходы, расходы и исполнение бюджета;
- аварийный центр с зонами отключения, прогнозом восстановления и подтверждением оповещения;
- календарь дома, бронирование общих помещений, гостевые пропуска и реестр автомобилей.
- QR-пропуска, безопасность, SOS, парковка и контроль работ по дому;
- события, RSVP, клубы, помощь соседям и совместные покупки;
- мульти-ЖК аккаунты, детальные роли и white-label настройки;
- AI-центр с анализом заявок/фото, ответами по источникам и проектами решений;
- offline-очередь, аналитика, rate limiting, CI и staging-конфигурация.

Платёжные сущности, квитанции, webhook и защита от повторной обработки реализованы в схеме. Проведение реальных платежей, SMS/push, команды СКУД/шлагбаума и ЭЦП остаются выключенными до подключения выбранных провайдеров и выдачи ключей.

## Быстрый запуск Web

Требования: Node.js, pnpm и проект Supabase.

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

Откройте `http://localhost:3000`.

В `.env.local` укажите URL проекта и anon key Supabase. `SUPABASE_SERVICE_ROLE_KEY` нельзя использовать в браузере и нельзя коммитить.

## Проверки

```bash
pnpm type-check
pnpm lint
pnpm build
pnpm test:smoke
pnpm exec playwright install chromium
pnpm test:e2e
git diff --check
```

Мобильный клиент проверяется из его каталога:

```bash
cd mobile
flutter pub get
flutter analyze
flutter test
```

Проверка безопасности:

```bash
pnpm security:scan
```

Сканер требует `OPENAI_API_KEY`, который передаётся только через окружение. Результаты в `strix_runs/` не коммитятся.

## Запуск Flutter

```bash
cd mobile
flutter pub get
flutter run \
  --dart-define=SUPABASE_URL=https://your-project.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=your-anon-key
```

Flutter использует те же Supabase URL и anon key, что и Web. Без них приложение показывает экран настройки конфигурации и не подставляет демонстрационные данные.

## База данных

Основная схема находится в `supabase/migrations/001_initial_schema.sql` и `002_rls_policies.sql`. Дополнительные исправления:

- `005_security_and_direct_chats.sql` — безопасные RPC для личных чатов, платежей и проверки жителей;
- `006_shared_post_media.sql` — доступ жителей одного ЖК к изображениям публикаций;
- `012_service_requests.sql` — заявки жителей, вложения, SLA, история, оценки и автоматические уведомления;
- `013_house_documents.sql` — документы ОСИ, версии, подтверждения ознакомления и доступ к файлам;
- `014_governance_finance.sql` — официальные голосования, бюллетени, счета, бюджет и финансовые операции;
- `015_emergency_alerts.sql` — аварийные оповещения и подтверждения жителей;
- `016_resident_services.sql` — календарь дома, бронирования, гостевые пропуска и автомобили.
- `017`–`025` — мульти-ЖК роли, white-label, доставка уведомлений, QR-доступ, парковка, работы, сообщество, маркетплейс, платежи, AI, reliability, правила бронирования и атомарное переключение объекта.

Для изменения PostgreSQL сначала прочитайте `supabase-postgres-best-practices`, добавьте новую миграцию и примените её через Supabase CLI:

```bash
pnpm exec supabase db push
```

После изменения схемы обновите типы:

```bash
pnpm db:types
```

## Важные правила

Авторизация и права проверяются Supabase RLS/RPC, а не только скрытием кнопок в UI. Не добавляйте тестовые аккаунты, фейковые списки или optimistic-изменения без rollback. При изменении функции, которая есть на Web, проверьте её эквивалент во Flutter.
